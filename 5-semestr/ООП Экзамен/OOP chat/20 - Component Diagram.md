# Диаграмма компонентов (Component Diagram)

## 1. Назначение

**Диаграмма компонентов** используется для:

* отображения **физической структуры программной системы**;
* показа **организации программных компонентов** и **зависимостей между ними**;
* описания того, **из каких файлов, библиотек и модулей состоит система** и **как они связаны**.

📌 Component Diagram отвечает на вопрос:
**«Из каких программных частей состоит система и как они зависят друг от друга?»**

---

## 2. Место в процессе проектирования

* Обычно строится **на поздних этапах проектирования**:

  * когда определены классы;
  * известны связи между ними;
  * сформирована архитектура.
* Особенно полезна для:

  * систем с **большим количеством классов**;
  * сложных модульных или клиент-серверных архитектур.

📌 Но допустимо:

* строить Component Diagram **для части классов** — для обучения и практики;
* уточнять и изменять диаграмму по мере развития проекта.

---

## 3. Что отображает диаграмма компонентов

Диаграмма показывает:

* программные **модули** (компоненты);
* **файлы исходного кода**;
* **библиотеки**;
* **исполняемые файлы**;
* **зависимости между ними** (кто от кого зависит).

❗ Она **не показывает поведение** и **не показывает логику выполнения** — только структуру.

---

## 4. Основные элементы диаграммы

### 4.1 Component (Компонент)

Компонент — это **модуль программного обеспечения**, например:

* файл исходного кода (`.cpp`, `.java`);
* заголовочный файл (`.h`);
* библиотека (`.dll`, `.so`);
* исполняемый файл (`.exe`).

📌 Компонент:

* может содержать классы;
* взаимодействует с другими компонентами через зависимости или интерфейсы.

---

### 4.2 Package (Пакет)

**Пакет** объединяет логически связанные компоненты:

* библиотеки;
* подсистемы;
* модули.

Используется для:

* упрощения структуры;
* группировки элементов.

---

### 4.3 Package Specification и Package Body

Часто используются **в паре**.

| Элемент                   | Назначение                              |
| ------------------------- | --------------------------------------- |
| **Package specification** | Определение интерфейса (например, `.h`) |
| **Package body**          | Реализация (например, `.cpp`)           |

📌 Аналогия:

* specification → объявление;
* body → реализация.

---

### 4.4 Dependency (Зависимость)

Связь **dependency** показывает, что:

* один компонент **использует** другой;
* для компиляции или работы **необходим другой компонент**.

Примеры зависимостей:

* использование классов;
* наследование;
* включение заголовочных файлов;
* линковка библиотек.

➡ Стрелка направлена:
**от зависимого компонента к используемому**.

---

## 5. Пример: клиент банкомата (Client.exe)

### Структура

* Каждый класс:

  * имеет `.h` (заголовок);
  * и `.cpp` (реализацию).
* Поэтому:

  * каждый класс представлен **двумя компонентами**.

### Пример зависимостей

* `Client.exe` зависит от:

  * `CardReader.h`
  * `CashDispenser.h`
* `CardReader.cpp` зависит от:

  * `Screen.h`
* Заголовочные файлы используются для:

  * компиляции `.cpp`
* После компиляции всех `.cpp`:

  * создаётся исполняемый файл `Client.exe`

📌 Это наглядно показывает:

* порядок компиляции;
* структуру зависимостей;
* архитектуру клиентской части системы.

---

## 6. Дополнительные элементы (из CASE-инструментов)

Некоторые инструменты позволяют дополнительно показывать:

| Элемент                       | Назначение                          |
| ----------------------------- | ----------------------------------- |
| **Main program**              | Главная программа (точка входа)     |
| **Subprogram body**           | Тело подпрограммы                   |
| **Task specification / body** | Потоки выполнения (многопоточность) |

Они применяются:

* при моделировании реальной программной реализации;
* для сложных систем.

---

## 7. Принципы ООП на диаграмме Component

Диаграмма отражает:

* **Модульность**
  → система разбита на независимые части
* **Инкапсуляцию**
  → компоненты взаимодействуют через интерфейсы и зависимости
