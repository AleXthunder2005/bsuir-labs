# Диаграмма классов (Class Diagram)

## 1. Назначение

**Диаграмма классов** — центральная диаграмма UML.

Основные цели:

* **проектирование структуры программной системы**;
* описание **классов, их атрибутов и методов**;
* задание **связей между классами**;
* **генерация исходного кода** на языках ООП (Java, C++, C# и др.).

📌 Это **единственная диаграмма**, по которой напрямую и массово **генерируют код**.

---

## 2. Роль диаграммы классов в проектировании

С помощью Class Diagram можно:

* спроектировать модель предметной области;
* проверить архитектурные решения;
* зафиксировать структуру системы перед реализацией;
* документировать систему.

⚠️ Не все модели на Class Diagram предназначены для генерации кода
(например, концептуальные модели).

---

## 3. Основные элементы диаграммы

### 3.1 Класс (Class)

Класс изображается **прямоугольником**, разделённым на 3 секции:

1. **Имя класса**
2. **Атрибуты (поля)**
3. **Методы (операции)**

Пример:

```
User
-----------------
- id : int
- name : String
-----------------
+ login()
+ logout()
```

Обозначения доступа:

* `+` public
* `-` private
* `#` protected

---

### 3.2 Связи между классами

Связи показывают:

* как классы взаимодействуют;
* как это повлияет на структуру кода.

❗ Вид связи **напрямую влияет на генерируемый код**.

---

## 4. Виды связей между классами

### 4.1 Association (Ассоциация)

**Простая связь без направления**.

* классы равноправны;
* не указывает, кто кого использует;
* **на код не влияет**.

📌 Используется:

* для концептуальных моделей;
* для анализа предметной области.

❌ Не рекомендуется для генерации кода.

---

### 4.2 Directed Association (Направленная ассоциация)

Показывает:

* один класс **хранит ссылку на другой**;
* один объект **использует методы другого**.

➡ В коде:

* появляется поле-ссылка на другой класс.

Пример:

```
Order → Customer
```

📌 Самая часто используемая связь при проектировании классов.

---

### 4.3 Aggregation (Агрегация)

Тип связи «**часть–целое**».

* один объект **содержит** другой;
* часть может существовать **самостоятельно**.

Обозначение:
**пустой ромб** у целого.

Пример:

```
Team ◇── Player
```

📌 Используется как **семантическое уточнение** ассоциации.

---

### 4.4 Association Class (Ассоциативный класс)

Используется, когда:

* связь между двумя классами **сама имеет атрибуты**.

Пример:

* Student — Course
* Enrollment (оценка, дата)

📌 В UML:

* ассоциативный класс связан с ассоциацией;
* **обычно не влияет на код напрямую**.

---

### 4.5 Generalization (Обобщение / наследование)

Показывает отношение:

* **родитель → потомок**

Обозначение:
**пустой треугольник** в сторону родителя.

Пример:

```
Animal
  ▲
 Dog
```

➡ В коде:

```java
class Dog extends Animal
```

📌 Ключевая связь ООП.

---

### 4.6 Realization (Реализация интерфейса)

Показывает:

* класс **реализует интерфейс**.

Обозначение:

* пунктирная линия;
* пустой треугольник.

Пример:

```
Printer ─ ─ ─▷ IPrintable
```

➡ В коде:

```java
class Printer implements IPrintable
```

---

### 4.7 Dependency (Зависимость)

Показывает:

* один класс **использует другой временно**;
* нет хранения ссылки.

Пример:

* передача параметра;
* локальный объект;
* вызов метода.

📌 Самая слабая связь.

---

## 5. Дополнительные элементы диаграммы

### Interface (Интерфейс)

* содержит только абстрактные методы;
* реализуется классами.

### Signal (Сигнал)

* асинхронное сообщение;
* без ожидания ответа.

### Enumeration (Перечисление)

* набор именованных констант;
* тип данных.
