## Декомпозиция системы

**Декомпозиция** — разбиение системы на **подсистемы**, чтобы упростить:

* разработку
* сопровождение
* параллельную работу команд
* настройку прав доступа
* интеграцию с внешними системами

**Подсистема** — это больше, чем пакет:

* классы
* интерфейсы
* реализации Use Case
* другие подсистемы

---

## Правила выделения подсистем (с примерами)

### 1. Факультативные части → отдельная подсистема

Если часть **необязательна** — выносим отдельно.

**Пример:**

* основной магазин
* подсистема рекомендаций товаров
  (если отключить — система всё равно работает)

---

### 2. Горизонтальное и вертикальное разделение

#### Горизонтальное

Подсистема = всё для одной функции

* Boundary + Control + Entity

**Пример:**
Подсистема «Заказы»:

* форма заказа
* логика оформления
* сущность Order

---

#### Вертикальное

Подсистемы по слоям

* UI
* бизнес-логика
* данные

**Пример:**

* UI-подсистема (все формы)
* Business-подсистема
* Data-подсистема

---

### 3. По актёрам

Каждый актёр → своя подсистема.

**Пример:**

* подсистема «Покупатель»
* подсистема «Администратор»

---

### 4. Сильно связанные классы — в одну подсистему

Классы, которые **постоянно взаимодействуют**, держат вместе.

Если класс **слишком большой** → делят и связывают через интерфейс.

**Пример:**

* Order + OrderItem + Payment
  (в одной подсистеме)

---

### 5. Уровни сервиса → разные подсистемы

Если есть разные **API / интерфейсы**.

**Пример:**

* REST API
* Web UI
* Mobile API

Каждый уровень — отдельная подсистема.

---

### 6. Зависимость от платформы / ОС

Код, зависящий от среды, выносится отдельно.

**Пример:**

* подсистема Windows
* подсистема Linux
* подсистема Android
