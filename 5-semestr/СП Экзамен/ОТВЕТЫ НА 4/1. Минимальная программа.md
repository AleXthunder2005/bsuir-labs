## 1. Минимальная программа для ОС Windows с окном на экране. Обработка сообщений Windows. Перерисовка окна по сообщению WM_PAINT.

**Окно** — это прямоугольная область на экране, через которую пользователь **взаимодействует с программой**.
Почти всё в Windows — это окна: программа, кнопка, диалог, панель.

Окно принимает:

* ввод с клавиатуры,
* клики мыши,
* системные сообщения (перерисовка, закрытие и т.д.).

---

## Основные элементы окна

Типичное окно Windows содержит:

* **Заголовок окна** — название программы.
* **Кнопки управления** — свернуть, развернуть, закрыть.
* **Рамка окна** — позволяет менять размер.
* **Рабочая область (клиентская область)** — место, где программа рисует содержимое.
* **Меню** (необязательно).
* **Полосы прокрутки** (если нужно).

---

## Родительское и дочернее окно

### Родительское окно

* Основное окно программы.
* Управляет дочерними окнами.

### Дочернее окно

* Принадлежит родительскому.
* Передает сообщения родительскому

📌 Примеры дочерних окон:

* кнопки,
* поля ввода,
* панели,
* диалоговые окна.

---

## Структура программы с событийным управлением

Программы Windows работают по принципу **событий**.

### Что это значит:

* Программа **не выполняется по порядку** от начала до конца.
* Она **ждёт событий**:

  * нажатие кнопки,
  * движение мыши,
  * перерисовка окна,
  * закрытие окна.

### Основные части:

1. **Цикл сообщений** — ждёт события от Windows.
2. **Оконная процедура** — функция, которая обрабатывает события.

## Минимальная программа Windows с окном

Минимальная оконная программа делает всего несколько вещей:

1. Регистрирует класс окна.
2. Создаёт окно.
3. Показывает его на экране.
4. Запускает цикл обработки сообщений.

## Создание и отображение окна (логика)

Процесс выглядит так:

1️⃣ **Регистрация класса окна**
Сообщаем системе:

* как выглядит окно,
* какая функция обрабатывает события.

2️⃣ **Создание окна**
Вызывается функция создания окна, но окно ещё **не видно**.

3️⃣ **Отображение окна**
Окно становится видимым (`ShowWindow`).

4️⃣ **Обработка сообщений**
Программа ждёт и обрабатывает действия пользователя.

---

## Как Windows управляет окном

* Windows посылает окну **сообщения** (`WM_PAINT`, `WM_CLOSE`, и т.д.).
* Оконная процедура решает, что с ними делать.
* Если сообщение не обработано — его обрабатывает Windows по умолчанию.

---

## **Перерисовка окна по сообщению WM_PAINT**

### 1️⃣ Что такое перерисовка окна

* Окно на экране может быть **закрыто другим окном**, уменьшено, скрыто или изменено.
* Чтобы содержимое окна снова стало видно, его **нужно перерисовать**.
* Перерисовка — это **отрисовка всего, что должно отображаться в окне** (текст, кнопки, графика).

---

### 2️⃣ Сообщение `WM_PAINT`

* Windows посылает окну сообщение **`WM_PAINT`**, когда нужно обновить содержимое.
* Сообщение получает **окошная процедура** (WindowProc) программы.

---

### 3️⃣ Как обрабатывается `WM_PAINT`

1. В окне вызывается функция `BeginPaint` — Windows даёт **контекст устройства (HDC)** для рисования.
2. Программа рисует всё, что должно отображаться.
3. В конце вызывается `EndPaint` — Windows отмечает область как **обновлённую**, и больше перерисовывать её не нужно.

---

### 4️⃣ Когда посылается `WM_PAINT`

* Окно стало видимым после перекрытия другим окном.
* Размер окна изменился.
* Программа вызвала `InvalidateRect` или `InvalidateRgn` — сигнал «нужно перерисовать эту область».
* Система сама решает, **когда послать WM_PAINT**, чтобы оптимизировать работу.

---

### 5️⃣ Пример кода

```c
case WM_PAINT:
{
    PAINTSTRUCT ps;
    HDC hdc = BeginPaint(hwnd, &ps);
    TextOut(hdc, 50, 50, "Привет, мир!", 12);
    EndPaint(hwnd, &ps);
}
break;
```

➡️ Эта обработка рисует текст в окне, когда приходит `WM_PAINT`.

---

### 6️⃣ Ключевые моменты для экзамена

* **WM_PAINT** — это сообщение о необходимости перерисовать окно.
* Перерисовка **выполняется в оконной процедуре**.
* Используются функции **BeginPaint / EndPaint**.
* Можно инициировать перерисовку принудительно через **InvalidateRect / InvalidateRgn**.

---

# **Алгоритм перерисовки окна в Windows (Invalidate → WM_PAINT → Validate)**

1. **Помечаем область как «грязную»**

   * Вызываем `InvalidateRect(hwnd, &rect, TRUE)` или `InvalidateRgn(hwnd, rgn, TRUE)`
   * Windows отмечает эту область в очереди обновлений, но сразу ничего не рисует

2. **Windows решает, когда перерисовать**

   * Система объединяет все «грязные» области окна
   * Генерирует сообщение `WM_PAINT` для окна

3. **Начало обработки WM_PAINT**

   * В оконной процедуре (WindowProc) обрабатываем `WM_PAINT`
   * Вызываем `BeginPaint(hwnd, &ps)`

     * Возвращает **контекст устройства (HDC)** для рисования
     * Также автоматически делает Validate на область, которую будем рисовать

4. **Рисуем содержимое окна**

   * Используем HDC для отрисовки текста, графики, линий и т.д.
   * Можно рисовать **только ту область, которая помечена как грязная**

5. **Завершение обработки WM_PAINT**

   * Вызываем `EndPaint(hwnd, &ps)`
   * Windows **помечает отрисованную область как чистую** (Validate)
   * Очередь обновлений очищается

6. **Всё готово**

   * Если другие области окна будут помечены `Invalidate*`, процесс повторится
   * Оптимизация: перерисовываются **только помеченные области**, а не всё окно

---

## 1️⃣ Что такое Validate

**Validate** = «пометить область как чистую, то есть больше не требующую перерисовки».

* Когда мы вызываем `InvalidateRect` или `InvalidateRgn`, Windows говорит:

  > «Эта область грязная, нужно её перерисовать»
* Эта область попадает в **очередь обновлений** (queue of dirty regions)
* Когда приходит `WM_PAINT`, мы рисуем её через `BeginPaint` → `EndPaint`
* **EndPaint автоматически делает Validate** — область считается **чистой**

Если вручную вызвать `ValidateRect` или `ValidateRgn`, мы говорим:

> «Да, Windows, эта область уже нарисована, можешь убрать её из очереди dirty regions»

---

## 2️⃣ Зачем вообще нужен Validate

1. **Чтобы не перерисовывать одно и то же каждый кадр**

   * Без Validate Windows думает, что область всё ещё грязная → пришлёт ещё WM_PAINT
   * Может получиться **бесконечный цикл WM_PAINT** и тормоза

2. **Чтобы контролировать частичную перерисовку**

   * Иногда рисуешь только часть окна
   * Остальное остаётся грязным → будет перерисовано позже

3. **EndPaint делает Validate автоматически**

   * Если используешь BeginPaint/EndPaint, вручную Validate не нужен
   * Если рисуешь **снаружи WM_PAINT**, тогда Validate может понадобиться, чтобы сказать Windows: «область обработана»
