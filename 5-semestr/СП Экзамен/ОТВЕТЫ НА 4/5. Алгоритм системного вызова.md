## 5. Алгоритм системного вызова в ОС Windows.

**Системный вызов** — это способ, с помощью которого **программа в пользовательском режиме просит ядро Windows выполнить работу**, к которой обычным программам доступ запрещён
(работа с файлами, памятью, процессами, устройствами).

> *Системный вызов в Windows — это контролируемый переход из пользовательского режима в режим ядра через NtDll.dll с последующей диспетчеризацией по SSDT и возвратом обратно.*

👉 Пример:
`CreateProcess`, `ReadFile`, `WriteFile`
— **не делают работу сами**, а в итоге вызывают **внутренние функции ядра** (Nt-функции).

---

## **Почему нужен переход в режим ядра**

Пользовательские программы **не имеют доступа** к:

* памяти ядра
* структурам процессов
* драйверам
* устройствам

Поэтому Windows:

* **переключает процессор в режим ядра**
* выполняет нужную системную службу
* **возвращает управление обратно в пользовательский режим**

Это защищает систему от поломки и взлома.

---

## **Общая схема вызова**

```
Приложение
 ↓
Windows API (ReadFile, CreateProcess)
 ↓
NtDll.dll (NtReadFile, NtCreateUserProcess)
 ↓
Переход в режим ядра
 ↓
Ядро Windows (ntoskrnl.exe / win32k.sys)
 ↓
Возврат в пользовательский режим
```

---

## **Роль NtDll.dll**

`NtDll.dll` — это **последний слой пользовательского режима**.

Она:

* содержит **Nt-функции**
* подготавливает системный вызов
* **переключает процессор в режим ядра**

Пример:

```text
ReadFile → NtReadFile → системный вызов → ядро
```

---

## **Как происходит системный вызов (пошагово)**

### **1️⃣ Подготовка вызова (в NtDll.dll)**

Nt-функция делает следующее:

1. **Кладёт номер системного вызова в регистр EAX**

   * у каждой Nt-функции есть свой номер
   * номер зависит от версии Windows

2. **Кладёт указатель на параметры в EDX**

   * параметры лежат в стеке пользовательского режима

3. **Выполняет специальную инструкцию процессора**:

   * `int 0x2E` — старые процессоры
   * `sysenter` — современные Intel
   * `syscall` — современные AMD

👉 Эта инструкция **заставляет процессор перейти в режим ядра**.

---

## **2️⃣ Попадание в ядро**

После переключения процессора:

* управление попадает в код ядра
* вызывается диспетчер системных вызовов:

  * `KiSystemService` или `KiFastCallEntry`

---

## **3️⃣ Поиск нужной системной функции**

В ядре есть специальные таблицы:

* **KiServiceTable (SSDT)** — адреса Nt-функций
* **KiArgumentTable** — сколько байт параметров у каждой функции

Ядро:

1. по номеру из `EAX` узнаёт:

   * сколько параметров
   * какую функцию вызывать
2. копирует параметры **со стека пользователя на стек ядра**
3. вызывает нужную Nt-функцию

---

## **4️⃣ Проверка параметров**

Если вызов пришёл **из пользовательского режима**:

* числа проверяются на допустимость
* указатели проверяются (`ProbeForRead / ProbeForWrite`)
* всё это делается в `try/except`, чтобы система не упала

👉 Это защита ядра от плохих или вредоносных программ.

---

## **5️⃣ Выполнение системной службы**

Nt-функция:

* выполняется **в режиме ядра**
* работает в контексте текущего процесса и потока
* может обращаться к пользовательской памяти (после проверки)

---

## **6️⃣ Возврат обратно**

После завершения:

* процессор возвращается в пользовательский режим
* используется:

  * `iret` — старые CPU
  * `sysexit` — Intel
  * `sysret` — AMD

Программа продолжает работу как ни в чём не бывало.

---

## **Системные вызовы из режима ядра (Nt vs Zw)**

### Проблема

Драйверы **уже работают в режиме ядра**, но:

* Nt-функции думают, что вызов пришёл из user mode
* и начинают проверять указатели → ошибка

---

### Решение: **Zw-функции**

* `ZwCreateFile`, `ZwReadFile` и т.д.
* **предназначены для драйверов**
* создают «искусственный» системный вызов
* правильно устанавливают **previous mode = kernel**

👉 В итоге:

* Nt-функция понимает, что вызов из ядра
* проверки пользовательских указателей не выполняются

---

## **Коротко для билета**

* Windows API вызывает **Nt-функции**
* Nt-функции делают **переход в режим ядра**
* Ядро находит функцию по номеру в SSDT
* Проверяет параметры
* Выполняет системную службу
* Возвращает управление в пользовательский режим
* **Nt — для user mode**
* **Zw — для kernel mode**
