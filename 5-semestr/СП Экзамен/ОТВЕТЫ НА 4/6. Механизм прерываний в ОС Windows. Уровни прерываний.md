# **6. Механизм прерываний в ОС Windows. Уровни прерываний**

---

## **1. Что такое прерывания и исключения (базовая идея)**

**Прерывания и исключения** — это механизмы ОС, которые **временно отвлекают процессор** от обычного выполнения программы и **передают управление коду операционной системы**.

Цель:

* быстро отреагировать на внешние события (устройства),
* обработать ошибки,
* выполнить системные действия.

В Windows процессор при этом передаёт управление **обработчику системного прерывания** — функции ядра, соответствующей конкретному событию.

---

## **2. Прерывания vs исключения (чётко и в таблице)**

| Критерий              | Прерывание                     | Исключение                                |
| --------------------- | ------------------------------ | ----------------------------------------- |
| Тип события           | Асинхронное                    | Синхронное                                |
| Когда возникает       | В любой момент                 | Во время выполнения конкретной инструкции |
| Связь с текущим кодом | Не связано                     | Прямо связано                             |
| Источник              | Устройства, таймеры            | Сам процессор                             |
| Можно ли запретить    | Да (обычно)                    | Нет                                       |
| Примеры               | Клавиатура, мышь, диск, таймер | Деление на ноль, page fault               |

**Пример:**

* Ты печатаешь код → нажал клавишу → **прерывание**
* Программа делит на 0 → **исключение**

---

## **3. Как обрабатывается прерывание в Windows (алгоритм)**

1. Возникает событие (например, сетевой пакет)
2. Устройство формирует **IRQ (Interrupt Request)**
3. Контроллер прерываний принимает IRQ
4. Контроллер:

   * превращает IRQ в **номер прерывания**
5. Процессор:

   * использует номер как индекс в **IDT**
6. Управление передаётся **обработчику ядра**
7. После обработки:

   * выполнение продолжается с того же места

---

## **4. IDT — таблица диспетчеризации прерываний**

| Параметр         | Описание                              |
| ---------------- | ------------------------------------- |
| Полное имя       | Interrupt Descriptor Table            |
| Назначение       | Связывает номер прерывания с функцией |
| Кто заполняет    | Windows при загрузке                  |
| Где используется | При каждом прерывании или исключении  |

👉 **IDT = массив указателей на обработчики**

---

## **5. Контроллеры прерываний**

### **x86**

| Контроллер    | Описание                          |
| ------------- | --------------------------------- |
| PIC (i8259A)  | Старый программируемый контроллер |
| APIC (i82489) | Расширенный, поддерживает SMP     |

---

### **x64**

| Особенность     | Значение                   |
| --------------- | -------------------------- |
| Совместимость   | Поддержка x86              |
| Главное отличие | **Только APIC**            |
| Без APIC        | Windows x64 не запускается |

---

## **6. ISR — Interrupt Service Routine**

| Параметр         | Описание                      |
| ---------------- | ----------------------------- |
| Что это          | Функция обработки прерывания  |
| Где работает     | Режим ядра                    |
| Когда вызывается | При возникновении прерывания  |
| Что делает       | Минимальная обработка события |

**Пример:**

* ISR сетевой карты:

  * подтверждает прерывание
  * копирует данные
  * планирует DPC

👉 **ISR — очень быстрый и короткий код**

---

## **7. IRQL — уровни запросов прерываний**

**IRQL (Interrupt Request Level)** — это **программный приоритет выполнения кода** в Windows.

| Архитектура | Диапазон |
| ----------- | -------- |
| x86         | 0–31     |
| x64 / IA64  | 0–15     |

Чем **выше IRQL**, тем:

* выше приоритет
* больше прерываний блокируется

---

## **8. Как работает IRQL (пошагово)**

1. Возникает прерывание
2. Процессор:

   * сохраняет состояние потока
   * **поднимает IRQL**
3. Вызывается ISR
4. После завершения:

   * IRQL понижается
   * состояние восстанавливается
5. Если накопились более низкие прерывания — они обрабатываются

---

## **9. Основные уровни IRQL (таблица)**

| IRQL | Название       | Что делает           | Пример                  |
| ---- | -------------- | -------------------- | ----------------------- |
| 31   | High           | Блокирует всё        | Критический код ядра    |
| 30   | Power Fail     | Отказ питания        | UPS сигнал              |
| 29   | IPI            | CPU ↔ CPU            | Синхронизация ядер      |
| 28   | Clock          | Системный таймер     | Переключение потоков    |
| 27   | Profile        | Профилирование       | Performance counters    |
| 26–3 | Device / DIRQL | Устройства           | Диск, сеть              |
| 2    | DPC / Dispatch | Отложенные процедуры | Драйверы                |
| 1    | APC            | Асинхронные вызовы   | APC в поток             |
| 0    | Passive        | Обычный код          | Пользовательские потоки |

---

## **10. Пояснение ключевых IRQL с примерами**

| Уровень | Пояснение                            |
| ------- | ------------------------------------ |
| HIGH    | Всё запрещено, прерывания копятся    |
| Clock   | Таймер ОС, управляет квантом времени |
| Device  | Приоритеты устройств                 |
| DPC     | Завершение работы ISR                |
| Passive | Можно всё: память, файлы, ожидания   |

👉 Например:

* `KeDelayExecutionThread()` ❌ нельзя выше PASSIVE
* `malloc/new` ❌ нельзя на DISPATCH_LEVEL

---

## **11. Типы прерываний по источнику**

| Тип                      | Описание               | Примеры          |
| ------------------------ | ---------------------- | ---------------- |
| Асинхронные (аппаратные) | От устройств           | Клавиатура, диск |
| Синхронные (внутренние)  | Ошибки инструкций      | Деление на 0     |
| Программные              | Специальная инструкция | Системные вызовы |

---

## **12. Маскирование прерываний**

| Тип                 | Описание         | Пример        |
| ------------------- | ---------------- | ------------- |
| Маскируемые         | Можно запретить  | IF-флаг в x86 |
| Немаскируемые (NMI) | Запретить нельзя | Ошибка памяти |
