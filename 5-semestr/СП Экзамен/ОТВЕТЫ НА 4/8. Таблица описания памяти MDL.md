## 1️⃣ Что такое MDL (Memory Descriptor List)?

**MDL (Memory Descriptor List)** — это структура данных в ядре Windows, которая описывает, **как виртуальная память процесса сопоставляется с физической памятью**.

Проще говоря: у нас есть буфер в виртуальной памяти (VAS — Virtual Address Space), и мы хотим знать, где именно в физической памяти (PAS — Physical Address Space) он хранится. MDL хранит эту информацию.

### Пример из жизни

Представь библиотеку:

* Виртуальная память — это «карточки каталога» с номерами книг.
* Физическая память — это полки с книгами.
* MDL — это список, где для каждой книги указано, на какой полке она лежит.

## 2️⃣ Структура MDL

```c
struct MDL {
    PMDL Next;              // Указатель на следующий MDL (цепочка)
    SHORT Size;             // Размер структуры MDL (включая массив страниц)
    SHORT MdlFlags;         // Флаги (например, где можно читать/писать)
    PEPROCESS Process;      // Процесс, которому принадлежит память
    PVOID MappedSystemVa;   // Виртуальный адрес памяти в ядре
    PVOID StartVa;          // Начальный виртуальный адрес буфера
    ULONG ByteCount;        // Размер буфера в байтах
    ULONG ByteOffset;       // Смещение до начала буфера в первой странице
};
```

**Разбор по полочкам:**

* **Next** — если у тебя несколько буферов, MDL можно связать в цепочку.
* **Size** — сколько всего занимает структура.
* **MdlFlags** — свойства (например, можно ли делать кэширование).
* **Process** — владелец памяти.
* **MappedSystemVa** — адрес, по которому ядро видит этот буфер.
* **StartVa** — адрес, где буфер начинается в виртуальном пространстве процесса.
* **ByteCount** — сколько байт занимает буфер.
* **ByteOffset** — если буфер не начинается с начала страницы, здесь смещение.

## 3️⃣ Функции работы с MDL

Вот основные функции и что они делают:

| Функция                        | Что делает                                                   |
| ------------------------------ | ------------------------------------------------------------ |
| `IoAllocateMdl`                | Создаёт MDL для буфера в виртуальной памяти                  |
| `IoFreeMdl`                    | Освобождает MDL                                              |
| `IoBuildPartialMdl`            | Создаёт MDL для части буфера                                 |
| `MmInitializeMdl`              | Инициализирует MDL                                           |
| `MmSizeOfMdl`                  | Возвращает размер MDL                                        |
| `MmBuildMdlForNonPagedPool`    | Создаёт MDL для непрерываемой (non-paged) памяти             |
| `MmGetMdlVirtualAddress`       | Возвращает виртуальный адрес буфера из MDL                   |
| `MmGetMdlByteCount`            | Размер буфера                                                |
| `MmGetMdlByteOffset`           | Смещение в первой странице                                   |
| `MmGetSystemAddressForMdlSafe` | Возвращает адрес памяти в контексте ядра                     |
| `MmProbeAndLockPages`          | Фиксирует страницы в памяти (не дадим им вытолкнуть на диск) |
| `MmUnlockPages`                | Разрешает операционной системе перемещать страницы           |
| `MmMapLockedPages`             | Отображает зафиксированные страницы в ядро                   |
| `MmUnmapLockedPages`           | Отвязывает отображение                                       |

## 4️⃣ Пример на пальцах

Допустим, у нас есть буфер размером **6 КБ**:

* Страница = 4 КБ → нам нужно 2 страницы.
* Буфер начинается на 1000 байт внутри первой страницы.

MDL будет содержать:

* **StartVa** — адрес начала первой страницы.
* **ByteOffset** — 1000 (смещение до начала буфера в первой странице)
* **ByteCount** — 6 КБ
* **Pages[]** — номера двух страниц в физической памяти

Теперь ядро может работать с этим буфером напрямую, зная, где физически лежат нужные данные.

---

## 5️⃣ Важно знать дополнительно

1. **MDL vs обычные указатели**

   * Указатель просто хранит виртуальный адрес.
   * MDL хранит информацию о **физических страницах**, что нужно для драйверов и DMA (Direct Memory Access).

2. **Partial MDL**

   * Иногда нужно работать с частью буфера → можно создать **partial MDL**, который ссылается только на часть страниц.

3. **DMA и MDL**

   * Драйверы используют MDL, чтобы настроить контроллер DMA, который читает/пишет прямо в физическую память, минуя виртуальные адреса.

4. **Защита памяти**

   * MDL фиксирует страницы, чтобы ОС не могла их выгрузить на диск, пока идёт работа с ними.
