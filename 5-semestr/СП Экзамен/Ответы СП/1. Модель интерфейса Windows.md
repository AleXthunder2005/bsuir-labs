## 1. Модель программного интерфейса операционной системы Windows. Нотация программного интерфейса. Понятие объекта ядра и описателя объекта ядра операционной системы Windows. Модель архитектуры ОС Windows.

Операционная система Windows предоставляет программам **специальный интерфейс** для работы с её возможностями — он называется **Windows API** (Application Programming Interface).

**Windows API** — это набор функций, которые приложение может вызывать в **пользовательском режиме**, чтобы:

* создавать окна,
* работать с файлами,
* управлять процессами и потоками,
* использовать графику, звук, сеть и т.д.

### Основные группы функций Windows API:

1. **Базовые службы** — управление процессами, потоками, памятью, файлами.
2. **Службы компонентов** — поддержка COM, OLE и других компонентных технологий.
3. **Службы пользовательского интерфейса** — окна, меню, кнопки, сообщения.
4. **Графические и мультимедийные службы** — графика, звук, видео.
5. **Обмен сообщениями и совместная работа** — почта, сетевое взаимодействие, совместная работа приложений.

## Нотация Windows API (венгерская)

Windows API имеет разные варианты в зависимости от архитектуры системы:

* **Win32** — для 32-разрядных приложений,
* **Win64** — для 64-разрядных приложений.

С точки зрения программиста это один и тот же API, но типы данных и размеры указателей могут отличаться.

## Объекты ядра Windows

**Объект ядра** — это внутренняя структура данных, которая существует **только в ядре ОС** и описывает системный ресурс, например:

* процесс,
* поток,
* файл,
* событие,
* мьютекс и т.д.

На самом деле объект ядра — это **участок памяти**, содержащий информацию об этом ресурсе.
Программа **не имеет прямого доступа** к объекту ядра и не может изменить его напрямую.

Это сделано для:

* защиты системы,
* сохранения целостности данных,
* возможности изменять внутреннее устройство ОС без поломки приложений.

---

## Описатель объекта ядра

**Описатель объекта ядра (handle)** — это число, которое приложение получает при создании или открытии объекта ядра.

Приложение работает **не с самим объектом**, а **с его описателем**:

* передаёт handle функциям Windows API,
* через него ОС понимает, к какому объекту обращается программа.

Один объект ядра может иметь **несколько описателей**, если им пользуются разные процессы.

---

## Модель архитектуры ОС Windows

Windows использует **двухуровневую архитектуру**:

1. **Пользовательский режим** — работают приложения и подсистемы Windows API.
2. **Режим ядра** — работает ядро ОС, драйверы и объекты ядра.

Приложения **не могут напрямую обращаться к ядру**, а делают это только через Windows API, что повышает стабильность и безопасность системы.
